Pulling is free and predictable. Porting uses your Claude account, about two to five dollars a model in our tests, takes seven to forty minutes, and can fail after spending. So it never happens behind your back: you ask for it. It tries three times and stops early on the same failure twice.

The agent reads untrusted files

So it runs in a sandbox.

Sandboxed while written

A model's config and card are untrusted input. Claude Code runs under bubblewrap; without it you must pass --unsandboxed, and try-port can't run.

Pinned to one MAX

A port is built against the MAX version omxconsole serves with; the skill's environment is pinned to the same one. After a MAX upgrade, a port may need redoing.

Ported code is code

The agent writes Python that MAX loads. At serving time it runs like any other model code: review it if that matters to you.

Equal, not "good"

The checks prove it matches the original model. They don't evaluate quality on your workload.

docs/PORTING.md "What you need", "Limits" · docs/plan.md (skill env pinned since 2026-10-13)
An agent reading files from the internet needs a sandbox, so Claude Code runs under bubblewrap. The port is pinned to the MAX version omxconsole serves with. Two caveats: the ported Python runs at serving time like any model code, and matching the original isn't the same as being good at your task.

How the console talks to it

Just HTTP. Replies come back as events.

struct Api(Movable):
    var http: Http
    var base: String

    def __init__(out self):
        self.http = Http()
        var url = environment("MXC_URL", DEFAULT_URL)
        self.base = String(url.rstrip("/"))

    def admin(self, var r: Request) -> Request:
        if environment("MXC_ADMIN_KEY") != "":
            return r^.header_from_env("X-Mst-Admin", "MXC_ADMIN_KEY").timeout(15000)
        return r^.header("X-Mst-Admin", "1").timeout(15000)

    def get(mut self, message: Int, path: String, id: Int = 0):
        self.http.send(self.admin(Request.get(message, self.base + path).tagged(id)))
omxcode examples/console/api.mojo · real code, trimmed
Real code from the Mojo console. An Api struct wraps the framework's Http effect; the admin header is read from the environment, not pasted into a string. And get doesn't wait: it sends a tagged request, and the reply comes back later as an ordinary event.
The poll

Timers are data, too.

def poll_core(mut self, info: Bool = False):
    self.api.get(GOT_MODELS, "/admin/models")
    self.api.get(GOT_METRICS, "/admin/metrics")
    self.api.get(GOT_SERIES, "/admin/series?range=5m")
    self.api.get(GOT_REQUESTS, "/admin/requests?limit=40")

def every(self) -> List[Every]:
    var out: List[Every] = [Every(3000, POLL_CORE), Every(5000, POLL_SYSTEM), Every(3000, POLL_JOBS)]
    var p = self.place()
    if p.page == "model" and p.tab == "benchmark":
        out.append(Every(1000 if self.bench.running else 5000, POLL_BENCH))
    # … logs, the add flow, keys add their own
    return out

The UI thread only decides; the requests and their waiting happen elsewhere.

Polling works the same way. The app doesn't start timers; it returns the list of timers it wants right now, from its state, and the framework diffs that list like it diffs the view. The window never blocks on the network, with no locks or callbacks.
The honest edges

What it doesn't do yet.

Linux + NVIDIA only

Whether MAX serves these models on Apple silicon is still to be checked on a Mac.

A MAX nightly

Public alpha on MAX 26.7 nightly. A port is tied to its MAX version.

Text-only porting

Vision and embedding architectures haven't been tried. Safetensors only; one GPU.

Porting can fail

It needs Claude Code and bubblewrap, and can fail after spending.

Parked models

Remote code (EXAONE) and ALiBi (BLOOM) don't port.

Two consoles

The server still ships the JavaScript console; the Mojo one isn't it yet.
