The UI thread

update() and view() only decide.

  • Every platform draws on one thread. At 60 fps it has about 16 ms a frame.
  • Slow work is a request, a timer or a job, on a worker thread.
  • Its answer comes back to update() as an ordinary event.
  • App state is only touched on the UI thread: no locks, no races, no "which thread am I on?"
# a network call: queue it; the reply comes back
# to update() as Event(FETCHED, ...)
self.http.get(FETCHED, "http://localhost:8000/api/orders")

# data work (a query, an import, a sort): a job;
# update() hears LANDED when it ends
self.running = start_ui_job(StepJob(self.orders.value(), self.filters))
def jobs_message(self) -> Int: return LANDED
docs/ui-threads.md "The idea in one paragraph" and "The rules for an app"
Every platform draws on one thread, with about sixteen milliseconds a frame at sixty hertz. The rule: update and view only decide. Anything slow is a request, a timer or a job, and its answer comes back as an ordinary event. State is only touched on the UI thread, so app code has no locks.

Inside a job

A job ends. The UI hears it at once.

# mojoui.jobs: background jobs (MX frame's `Job`) that wake the UI the moment they end, instead of waiting for the
# app's next poll at a display frame.
# …
# How: the job's completion callback (mxframe.start_job_then, on the job's own thread) writes one byte to a pipe the
# host made (wake_pipe); the host watches the pipe's read end on its main loop (GTK: g_unix_fd_add; the web host: a
# thread blocking on it) and sends App.jobs_message() to update() at once. On Apple there is no pipe: the callback asks
# the app's delegate (the AppKit host's target) for `jobsEnded:` on the main run loop's next turn, …

def start_ui_job[B: JobBody](var body: B) -> Job[B.Out]:
    """mxframe.start_job, plus a wake of the UI when the job ends (done, failed or cancelled)."""
    return start_job_then(body^, WakeUI())
  • A job owns its inputs: a snapshot or a copy, never a reference to app state.
  • Linux: a finished job reaches update() in 0.02–0.05 ms (median).
  • Nothing else crosses threads: update() reads the result with poll().
mojoui/jobs.mojo · real comment and code, trimmed · docs/ui-threads.md (platform table)
When a job finishes, its own thread writes one byte to a pipe that GTK's main loop is watching, so update hears about it in a few hundredths of a millisecond. On Apple there's no pipe, so the job asks the main run loop to call us. A job owns a copy of its inputs, so nothing else crosses threads.

Proof, not promises

A watchdog names every slow frame.

def _slow(self, what: String, name: String, t0: Int):
    """Prints a SLOW: line when the work that started
    at t0 took longer than the budget."""
    if self.budget_ns <= 0 or t0 < self.armed_at:
        return
    var took = now_ns() - t0
    if took > self.budget_ns:
        print("SLOW: " + what + " " + name + " " + ms(took) + " ms", flush=True)

Safe by construction

The screen is the permission model.

A disabled button is no tool

If a person can't press it, an agent can't call it.

Dialogs are temporary

A dialog's or a context menu's items are tools only while it's open.

Mistakes teach

A wrong name or value comes back as an error listing the tools, so the agent corrects itself.

Where Mojo pushed back

What I'd tell the next person.

FFI is narrow

Scalars and (pointer, length) strings only, never structs by value. Exports can't raise.

A SIMD scratch crash

A SIMD vector indexed at run time as scratch (stack[sp] = v) segfaults the compiler, no message. stack_allocation[n, T]() works.

No official phone target

The iPhone build needs two runtime functions; a small, labelled C shim stands in (KGEN_CompilerRT_AlignedAlloc / AlignedFree).

The language moves

fn is deprecated, @value is replaced by @fieldwise_init, UnsafePointer is deprecated for Pointer. Fetch the docs, don't guess.

CLAUDE.md "Mojo rules that bite" (Mojo 1.1.0) · spike/kgen_shim.c (unofficial) · README.md "Why Mojo, honestly"
Where Mojo pushed back: FFI is scalars and pointer-length strings. A run-time-indexed SIMD scratch vector crashes the compiler silently; stack allocation works. No official phone target, so a small labelled C shim stands in for two runtime functions. And the language moves fast, so I fetch the docs.
The honest edges

What it can't do yet.

Mojo is young

Version 1.1, a small ecosystem, no Windows release. Flutter and React Native are far ahead on maturity.

iPhone only builds

It compiles and signs. It hasn't run on a phone, and its jobs still run on the main thread.

Android is partial

19 of 174 components run on the emulator by a check.

The Mac is on loan

Checked on GitHub's virtual Macs; the matrix counts Mac components as "builds".

NVIDIA first

Apple's GPU through Metal is checked on CI Macs only; real MacBook numbers aren't measured.

One wait left

A median over 100M rows in memory still makes the window wait about 0.7 s.
