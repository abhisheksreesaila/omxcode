How it's built

Four layers. Each only adds.

components.css parts, scoped under .oq-root

  • Plain HTML, CSS and JS. No framework, no build step.

  • Components read var(--oq-*) only, so a family can repaint all of them.

Real springs, in plain CSS

A spring is a linear() curve.

.oq-root {
  --oq-radius-card: 14px;  /* families set 12 / 16 / 22 */
  --oq-target: 36px;       /* families set 34 / 40 / 48 */
  --oq-spring-fast: linear(0, 0.02, 0.071, 0.142, … 1.019, 1.021, 1.023, 1.023, … 1.001, 1); /* k380 c30 */
  --oq-spring:      linear(0, 0.023, 0.079, 0.154, … 0.998, 0.999, 1);                   /* k170 c26 */
  --oq-spring-slow: linear(0, 0.045, 0.161, … 1.148, 1.165, 1.163, … 1.002, 1);      /* k260 c16 */
  --oq-spring-fast-dur: 300ms; --oq-spring-dur: 710ms; --oq-spring-slow-dur: 790ms; /* phone */
}
/* yours: a new part, built only from tokens */
.receipt { border-radius: var(--oq-radius-card); min-height: var(--oq-target);
  transition: transform var(--oq-spring-fast-dur) var(--oq-spring-fast); }

Stiffness and damping in the comment; the curve sampled into CSS. Reduced motion turns springs into fades.

src/tokens.css lines 18, 25, 28–31 (trimmed) · src/omxqua.js line 10 (prefers-reduced-motion)
The springs are real damped springs, stiffness and damping in the comment, sampled into CSS's linear function. No JavaScript animation loop: the browser runs it. Your own parts use the same tokens, and reduced motion turns springs into fades.
The motion budget

The more often it happens,
the less it moves.

280ms

Settle. Panels, sheets: fade and a 12 px rise. No bounce.

220ms

Gentle. Menus, popovers, toasts. Out in 150 ms.

0ms

None. Anything repeated many times a minute.

Springs only for small things under your finger. A press squashes to 0.90 small, 0.96 medium, 0.985 large, so it feels the same at every size.

LANGUAGE.md "Motion budget" · AGENTS.md lines 204–212 · src/omxqua.js lines 3, 13, 136–138
Springs are easy to overdo, so there's a budget: the more often something happens, the less it moves. Panels settle in 280 milliseconds, menus ease in over 220, and anything frequent doesn't animate. The press squash scales with size, so small and wide buttons feel the same.

The honest edges

What it isn't, yet.

One bit of glass

The nav pill and tab bar are frosted (58 %, 20 px blur). Every card, menu and dialog stays solid.

Mostly web

It's CSS and JS. The Mojo apps carry their own themes; only the Developer family is ported.

Some glue is inline

Dialog and sheet open/close and menu placement live in the showcase, not in omxqua.js.

One contrast gap

The field outline is 1.3:1 against its card, below WCAG's 3:1 for a control's edge. Noted, not fixed.
