## What we found first (2026-11-17)
- A card's resize already waits for the drag to end (GTK's on_board_drag_end); it then "snaps" because the Board is exactly
  the window's height (omxplorer `board_h`: "nothing scrolls") and mojoui.tiling clamps every split so each neighbour keeps
  its minimum. So "expand a card" and "the canvas grows" are one change: a Board taller than the window, which scrolls.
- mojoui.links already holds each table's columns (`Links.schemas`, fed by omxplorer `know_tables`); the typed-link field is a
  plain TextField whose every keystroke reaches `update` (LINKS_DRAFT). Video cards have `file`, `t` and `frame`.
