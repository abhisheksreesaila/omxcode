# Personal Note on omxcode: the gap audit

2026-11-17 (first written 2026-10-31, base `cc33c9d7`). Could omxcode build Personal Note (`~/Projects/personalnotev2`) the exact same way, with the same or better feel? This audit checks every feature against the framework (`mojoui/`). It doesn't build anything. The data is in [personalnote.json](personalnote.json) for the scoreboard. An older, shorter audit is `personalnotev2/docs/research/omxcode-gap-audit.md`; its probes (Sketch, Jot, Dictate, Keeper, Recall) have been built, so this one replaces it.

New since 2026-10-31: the owner decided the editors must be **native Mojo**, drawn by mojoui on a Canvas through a Painter, never JS, CodeMirror or a WebComponent. Every feature now has a **Native** mark. ❌ means the omxcode piece is a JS widget (mx-editor, CodeMirror) or a toolkit widget that can't be drawn on a Canvas. A feature with a ❌ is never counted as **have**, even if it works today.

## Verdict

**Partly, not the same way today.** Storage, search, voice, HTTPS, child programs, background work and the shell are there and often faster. Undo has landed. The editing heart (a native text editor, Markdown on a canvas, objects, mind maps, ink tied to text) is not built yet, and goal 74 is building it now.

- 53 features: **19 have (36%)**, **23 partial (43%)**, **11 missing (21%)**. On 2026-10-31 it was 18 have, 22 partial, 13 missing.
- 16 of the gaps still block a faithful rebuild. Most of them sit in the editors: native text, Markdown, canvas objects, mind maps and ink tied to text. These are what a user of Personal Note touches every minute.
- 3 features rest on a non-native piece today: Markdown drawn on the canvas (views, not a Painter), editing canvas text in place (a toolkit field and CodeMirror), and the Markdown page editor (CodeMirror). They stay **partial** until the native version exists.
- Where omxcode is already ahead (measured): keyword search, search by meaning, dictation, pan and zoom, saving on close, running with the window closed, and agent access without a hand-written CLI. Details under **Wins**.
- Hosts: nearly everything that works runs on Linux (GTK) and the web, checked by tests. HTTPS, child programs and hashing are Linux-first (Flare's shims aren't built for iPhone or Android; the Mac is unrun). The Mac builds but has never run. The phones are early. Personal Note's own target is the desktop (Linux and Mac), so the Mac run is the next platform risk after the gaps.

Checked in this audit by running them: `tests/test_history.mojo` (history ok, coalesce ok, cap ok). Checked on 2026-10-31 and not re-run: `tests/test_sqlite.mojo` (FTS5 ok), `tests/test_ink.mojo` (ok) and `tests/test_tray.mojo` (all ok, including notify; only on a private D-Bus, since a real panel on the owner's desktop makes it fail). Search by meaning (goal 44, Recall) passes its checker on branch `goal-44-recall`, but that branch **still isn't merged into main** (`git merge-base --is-ancestor goal-44-recall HEAD` says no). What main has of it is `mojoui.textembed`: sentence vectors in the app's own process (MiniLM-L6 through `mojoui.maxrt`). The top-k store (`mojoui.vectors`) and the bge-small indexer are only on the branch.

## What changed since 2026-10-31

- **HTTPS client:** `mojoui.http_flare` (https://, redirects, compressed replies) behind `mojoui.http`; `mojoui.apiclient` (bearer, OAuth, GraphQL paging, retries) talks to Stripe and Google in goal 57. Linux only so far. This closes the old "no HTTPS" gap.
- **Child programs:** `mojoui.process` starts and supervises a program (log, health check, stop the whole group, idle time). `mojoui.hf` downloads models with progress and resume.
- **Crypto, part:** `mojoui.crypto` has HMAC-SHA256, OS random tokens, base64url, constant-time compare, signed seals and PKCE; `mojoui.signin` does a desktop sign-in on a loopback redirect. It does **not** have AES-GCM or scrypt, so secure notes are still missing. There is still no keychain.
- **Server and plumbing pieces:** `mojoui.schedule`, `mojoui.webhooks`, `mojoui.static`, `mojoui.mail`, `mojoui.files`, `mojoui.tiling`, `mojoui.links`. Personal Note needs only `schedule` (reminders) and `files`; the rest are for omxcode's own server apps and don't move this score.
- **Undo:** `mojoui.history` (goal 74 M1) is generic: steps, coalescing, a redo branch, a cap. Test run in this audit.
- **Not built yet:** `textedit`, `mdedit`, `objectlayer` and `mindmap` (goal 74 M2 to M5) are not in this checkout, so those rows are unchanged.

## Ordered gap list (the shortest path)

Good showcase videos come first. Then come the gaps that block the rebuild without making a good video. Each item is a generic `mojoui` component with its own test, never an app hack. Items marked [goal 74] are what this goal builds; the rest wait.

1. **merge goal 44 + CommandPalette composite + the cut-off rule** (S, this week). Gap: Search by meaning not on main (only the embedder is); no command palette. Unblocks: Search by meaning: local embeddings, background indexer, score cut-off; Omnibar (Ctrl+K): grouped results, filters, preview, arrow keys, actions.
2. **mojoui.history (goal 74 M1)** (S, done) [goal 74]. Gap: DONE: no generic undo. Unblocks: Undo and redo with edits merged.
3. **mojoui.textedit: a text editor drawn on a Canvas through a Painter (caret, selection, wrap, hit tests, undo)** (M, goal 74) [goal 74]. Gap: No native multi-line editor. Unblocks: Edit canvas text in place, Markdown symbols hidden except on the caret's line; Markdown page editor (GFM tables, task lists, styled source, spellcheck).

Unblocks: Objects on the canvas: text boxes, stickies, shapes, pictures; select, move, resize, rotate, lock, z-order, nudge, select all; Arrows between objects that re-route when an end moves.

7. **text anchors + an ink layer over the native text view** (L, after goal 74). Gap: No ink anchored to text. Unblocks: Ink over the page: pen draws, finger scrolls, drawings folded behind a word; Ink marks anchored to words that follow the text when it reflows.
8. **AES-256-GCM + scrypt + HKDF (libcrypto at run time) + SecretStore (libsecret / Keychain)** (M, Dec 2026). Gap: No encryption beyond HMAC, and no keychain. Unblocks: Secure notes: AES-256-GCM, scrypt passphrase, recovery key, lock after 5 idle minutes; Keys and API tokens in the keychain; X bookmarks: OAuth PKCE sign-in, hourly sync into notes.
9. **mojoui.zip** (S, Dec 2026). Gap: No zip. Unblocks: Markdown + assets ZIP; Obsidian vault export and import.

Unblocks: Due dates and reminders: a notification, missed ones on launch, click jumps to the node; Focus mode: words only, full screen, word count; Insert pictures (picker, drop, paste), shrink to 1,400 px off the UI thread, stored by SHA-256.
11. **small composites on HTTPS + Process (already built) and MindMap** (M, Dec 2026). Gap: Provider-settings Test button; Jam; hash check on model downloads. Unblocks: AI settings: Claude Code CLI, Azure or OpenAI-compatible; a Test button; Jam: talk over a mind map, an LLM adds branches, reacts and suggests; Download models in the app with SHA-256 checks and resume.
12. **the system's print dialog (GtkPrintOperation / NSPrintOperation) with page setup** (M, Dec 2026). Gap: No print dialog. Unblocks: Print preview and print, Letter or A4.

Later, not blocking on the desktop: Mac platform calls (Touch ID, hiding from screen capture, the microphone), touch on real phones, installers and notarization. The Mac items need the owner's Mac. Phone touch needs real hardware (2027).

Honest ETAs: *this week* is S work that reuses pieces already proven. *goal 74* is the native editors, one milestone each. *Dec 2026* is anything that loads another system library or needs a platform dialog. *2027* is anything that needs hardware the checks can't reach.

## Wins (where omxcode would beat the original)

- **Keyword search and opening a big notebook.** Jot vs SQLite-wasm on OPFS at 1M notes: search p95 64.6 vs 165.8 ms (2.6×), cold open 65.8 vs 435.3 ms (6.6×), goal 42. Personal Note itself uses server-side SQLite, so against it: unproven.
- **Search by meaning in one process on the GPU.** Recall: top-10 over 1M in 2.2 ms, 7.7 ms p95 as you type (goal 44, unmerged branch; only mojoui.textembed is on main). Personal Note scores in a Python loop; at 1M its per-row loop takes seconds per query (D-1519, 3 queries). The side C race against its llama.cpp helper has no recorded result yet: unproven.
- **Dictation latency.** whisper-large-v3-turbo in process: 140 ms vs transformers.js 912 ms, same WER (goal 43). Against Personal Note's nemo-speech server over a WebSocket: unmeasured.
- **Pan and zoom with lots of ink.** Sketch: pan, zoom and draw p95 ≤ 3.5 ms with 101k points (goal 40). The older audit quotes Personal Note's zoom p95 as 97 ms, on another machine: not a fair race yet.
- **Saving on close and running with the window closed.** App.closing() runs in the same process (no 64 KiB keepalive request, no server lingering after close); background mode, tray and notifications checked (goal 45). Personal Note stops voice when the window closes.
- **Agent access without writing a CLI.** Every omxcode app is MCP tools through the agent host (docs/agent.md); Personal Note hand-wrote a 470-line CLI and 60 routes.
- **HTTPS, child programs and schedules in the same process.** mojoui.http_flare (https://), mojoui.process (start, health-check, stop a model server's whole group), mojoui.schedule (cron in a time zone, missed slots caught up once), mojoui.hf (resumable model downloads). Goals 50, 55, 66. Personal Note reaches the same things through a Python server and its helpers over loopback; no speed race recorded.
- **One program instead of three.** Personal Note is Python server + JS page + llama.cpp + nemo-speech processes over loopback; omxcode runs UI, search, embeddings and speech in one process (docs/probes.md). Fewer moving parts is measured in lines only in goal 44 M5, not yet recorded.

## What Personal Note doesn't need

Personal Note has no tray, no global hotkey, no file watching, no service worker, no wikilinks or backlinks, and no cloud sync apart from the X import. So omxcode's Keeper pieces (tray, watcher, background mode) are wins on offer, not requirements. Personal Note's three helper processes (the Python server, llama.cpp and nemo-speech over loopback) become one process in omxcode. Its 60 HTTP routes become plain function calls, because the UI and the data live in the same program. The server pieces added since (`webhooks`, `static`, `mail`, `accounts`, `billing`) are for omxcode's own web apps; a local notebook doesn't need them.
